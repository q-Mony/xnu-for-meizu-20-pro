Review of in-progress source, not final rejection until executor stops. No device actions or source edits by Sol.

- sleh: bounded copy currently happens BEFORE busy/dedup/slot quota, so after eight slots every further SpringBoard fault still copies user memory. Reserve an immutable slot with scalar identity under atomic busy first, unlock, then fill that owner slot stack and submit callout. Competing dedup reads immutable scalar fields only. Rejected/duplicate/full/busy paths must perform zero copyin.
- sleh: fp=0/sp=0 passes fp_valid then fp-0x60 underflows. Guard lower-bound and upper-bound entire window/canonical SP, and checked frame reads at FP+16; distinguish short copy and do not expose partial words after error. Avoid reading more total stack data than documented caps.
- lifecycle: receive_end matches only current server thread, not the exact invocation that observed this kmsg. Nested/unrelated receives during copyout can fill the wrong end. Carry an invocation token returned by receive_begin through mach_msg_receive_results to receive_end, just like existing meizu_receive_sequence, no kmsg kept after free.
- lifecycle: recv and reply share server_{pid,taskgen,tid}; a reply from another thread overwrites receiver identity. Keep separate identities and exact receive invocation association.
- lifecycle: os_atomic_load calls shown with only one argument are incompatible with ordinary XNU two-argument macro; verify actual production ARM64 TU. More fundamentally, active is read atomically outside lock but written plainly inside pure helper: mixed atomic/non-atomic access races. Release/acquire publication must be consistent, or remove unlocked mutable fastpath in favor of try-lock after cheap ID check. Counters printed outside lock must be copied into immutable snapshot under lock or atomic throughout.
- lifecycle: try-lock failures currently return silently, so dropped=0 would not imply complete observation. Count each failure per stage atomically and snapshot counts consistently. Missing events with any loss/expiry must remain unknown rather than no receiver/no reply.
- lifecycle: compute any metadata while a local ref is certainly owned, before transferring the pinned port to a row that a drainer may retire; keep exactly-once puts outside lock. Test request rejection and pointer reuse after retirement.
- lifecycle: finish matching by seq only is fragile if unrelated operations can call it; validate stable sender taskgen/tid too (sequence globally unique can be documented/tested). No state reuse allowed.
- lifecycle: sender can finish on one CPU before server send syscall returns; don't silently conclude missing reply-end means no send. Record late flags or give bounded finish grace and preserve the limit.
