## 实际改动

- 修正真实根盘读取路径：连续请求在既有 128 KiB 缓冲内合并。128 KiB 请求由 8 条 READ(10) 减至 1 条，保留 8 个 16 KiB 完整认证；全部认证成功后才复制该批次。
- 小请求只读必要认证单元；处理窗口内偏移、尾部、读错、批次内任意认证失败。前面成功的批次保留完成量，短复制沿用既有语义。
- 每 200 次既有 autolog 调用输出一条 `nova: rootio` 全局统计，携带真实计数器和频率。调用次数不是秒数。可区分命令数量、传输路径、认证、最终复制的累计开销。
- 保留上一轮 256 KiB 上层读取与 SHA 优化，固定此前成功包的 bootargs、UEFI、ADT、trust cache 和 Data seed。本轮不混入 SMP 或服务逻辑变化。

## 真机比较方式

维持相同 Boot 菜单起点，分别记录到 Apple、到 Hello 的秒数，再取回 MEIZULOG。旧成功基线两轮为 237 秒与 190 秒，起点相同，47 秒差异仍未解释。

旧日志 23 次大型签名转换共约 49.485 秒，其中 read 路径 41.027 秒、该路径自身 hash 8.431 秒；SpringBoard 串行等待 launchd/lsd 下界 136.277 秒。两组耗时有重叠，不能相加。新统计的 read_ticks 同样包含锁等待、轮询及传输内部拷贝，不等于纯介质延迟。

若读取合并改善有限，下一项按测量结果推进 LaunchServices 首次建库/容器扫描、诊断开销或 CPU 并行度；每轮单独比较。当前成功包确实未启用额外 CPU 探测，但没有运行时逐核证据，且其他基线的双核试验未到 Hello，因此不直接开启全部核心。

## 本轮真机日志结果

保留日志 SHA256 `283735861cf23fa8581a73728ee76961cd593a2658d2762bc4c9efe47af149aa`，无 dropped/NUL；35 条 rootio 快照严格解析通过、没有计数回退。

相同23次大文件转换、相同2,724,626,432字节及10,403次高层读取：总计44.002秒，read35.538秒、hash8.435秒。相对上轮49.485秒节省5.483秒，说明底层合并在这段路径有效；不能将其说成总开机提速。

rootio首末快照相隔344.546秒，期间累计传输路径11.010秒、认证33.474秒、最终复制0.941秒；认证失败增量0，平均成功命令约79.3KiB。这是包含Hello之后运行的采集窗口，不是Boot到Hello的阶段预算；成功块/命令比表明连续块确实被合并，但小请求和尾块不会总达到128KiB。

SpringBoard同线程的launchd、lsd串行等待观测下界仍约131.954秒，分别28.281秒、103.673秒。launchd采样数量和时点变化，不把下界减少直接称为服务加速。日志还保留3次Setup watchdog；后两次发生在第一条rootio后超过262秒，不能将其算作245秒首次Hello之前的延迟。
