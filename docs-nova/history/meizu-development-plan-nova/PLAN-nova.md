# 魅族 20 Pro 开发计划 — Nova

版本：v1.17，2026-10-30。初建时为新文件；本次调整前已备份。用户要求先解决启动慢；R14已真机成功启动并由用户确认Hello（单次，不作单一因果或净提速声明）。R15 sblong诊断探针已按Sol七项（六项观测+arm-lock竞态）review修正并在本地完成red→green主机测试、静态lock-region检查、真实ARM64 TU、增量内核构建、96MiB仅内核封包与审计；初版与f496修正候选均已被明确SUPERSEDED，arm-lock候选状态BUILT_AWAIT_NEW_USER_INSTALL_COMMAND；没有新安装命令前不刷入、不切槽、不重启。

目标：把现有可启动的 Nova 系统逐步推进到可触控、能显示真实电量、能发现蓝牙设备、能联网并使用 A740 图形与本机 DPU 的首版；更完整的蓝牙、充电、省电和高刷分别推进。

当前调研已完成，依据见[适配总报告](<nova-root>/artifacts-nova/hackios-port-review-nova/REPORT-nova.md)。开发项均从“待开始”记起，既有源码或作者的一加验收不折算成魅族开发项完成。

## 推进方式

- 用户指定优先顺序：P01 基线及所需 P02 计时 → S 启动优化 → P03 硬件依赖 → T 触控 → B 电池 → R 蓝牙发现 → W Wi-Fi → G 图形 → D 显示 → I 联合交付。先缩短每轮启动等待，再逐项推进驱动。
- 一次只推进一个开发项。每项完成后记录改动、验证、日志/镜像路径和遗留问题，再进入下一项；不在同一候选里混入未验收模块。
- 当前进行：**S03.4 SpringBoard→launchd 精确完成/调用者观测（arm-lock修正版）**。R14已成功启动到用户确认Hello；同锚点`SB→first Setup=46.176911094s`、`launchd→SB=21.094823698s`；前19.796s内cs4k 23段union`19.326s`（read`10.900s`/hash`8.403s`）。R14 SB-main `seq200/send_id6001009` WAIT phase age `27.246s`，无完成行/调用者。R15 arm-lock修正：所有`nova_sblong_summary`/`nova_sblong_long_ticks`初始化在`meizu_sb_ipc_capture`既有`meizu_ipc_lock`内，`.armed`最后发布；保留8行scalar槽、首send backtrace、LONG完成backtrace、recv_id/clock/稳定slot、10s bounded summary。静态lock-region检查通过；green ASan/UBSan 0失败；真实ARM64 object `69ddaecc…`、raw `e16b7a69…`；96MiB candidate `53470de0…`，状态BUILT_AWAIT_NEW_USER_INSTALL_COMMAND/installation_allowed=false。初版`6887a6d0…`与f496候选`025b1c1c…`均SUPERSEDED，不是可选安装项。BBS正向绑定`6001009`→`_BKSDisplayGetMainScreenInfo` header offset20，是客户端模板绑定，不是launchd-native opcode，也不证明运行期因果。没有新安装命令前不做设备操作；不声称根因修复、R15 Hello或提速。
- 表内“前置”是硬依赖，默认排序是推进偏好。S01–S03 技术上可在 P 阶段之后提前；D01–D02 也可在 GPU 就绪前开发，但本轮不并行改多个模块。
- B03 等项目若发现缺少完整远端启动或公共传输能力，按实际情况增加 B03.1 等子项，写明独立验收与依赖。阻断项保留为阻断，不能用模拟成功推进；可继续不依赖它的项目，但不能因此声明相关功能完成。
- 每次需要设备时核对当时的设备占用、授权和分区状态，沿用会话内已有授权范围，不对同一已授权动作重复索取许可。
- 所有改动、构建、备份和交付都在 Nova；修改已有文件先备份，更新 CHANGELOG。每项完成时保留第三方来源、许可和固件版本。
- 本表是当前证据下的完整开发清单。功能发现出的子任务纳入同一编号体系，不承诺未核实的工期、帧率或启动秒数。

## 完成标准与记录

状态使用：待开始 → 进行中 → 待设备验证 → 已完成；受硬依赖限制时标为阻断并记录原因。仅代码存在、链接通过或主机测试通过，不能将硬件开发项标为已完成。

每项关闭前记录：实际修改范围、输入/产物哈希、与变更相符的测试和真机证据（若适用）、回退入口、已知限制。计划里的 30 分钟/3 次是建议验收下限，进入该项时可按实际故障与负载细化，不代表当前已通过。

首版里“蓝牙可用”的范围写为**原生发现**；配对、GATT、HID、音频另有 X 项。“电池可用”指真实遥测和原生上报；充电控制与快充另有 X 项。首版是工程验收版本，不等于全应用兼容或日用电源管理完成。
